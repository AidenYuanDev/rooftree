# Blog 计划与进度

这是博客的工作清单（原来在 `blog` 分支上，现在都在 `main`），用来跨会话记录进度。完成一项就把 `[ ]` 改成 `[x]`，并在后面写上 commit。
设计上的决定（为什么这样做）记在每一节的"约定"里，改动约定要先和作者确认。

## 总体约定

- 架构：HTTP、WebSocket 和以后的游戏连接，**只在网络线程上解析**，然后排进会话队列，由**主线程按帧处理**。
  这套核心（会话、主循环、AntiDOS）是框架模块，blog 和以后的游戏服共用代码；原定各自一个进程，2026-10-29 作者改成**同一个进程、同一帧**（docs/29 §3.1.1）。
  - 每个会话每帧最多处理 3 条消息（可配置）；2026-10-29 作者决定和以后的游戏服共用 100（压测：一个地址狂刷不限流的读请求时，其他读者的吞吐 -71%，3 条时是 -30%）；
    每帧总预算可配置，按性能测试结果定（框架开销每条 35–60 ns，见 docs/29 §3.9）。
  - AntiDOS 按消息类型配置"N 秒内最多 M 次"，超过后按策略记日志、拒绝或踢出。
  - 帧间隔用最短间隔方式（`MinUpdateDiff`），blog 默认 5ms（2026-10-29 压测后改为 2ms：API 请求要等两帧，固定延迟从约 10ms 降到约 4ms）；主线程卡住超过 `MaxCoreStuckTime`（默认 60s）就主动崩溃，由 systemd 重启。
  - 主线程不阻塞：Argon2、发邮件放 ThreadPool，数据库走异步回调。
- 只用 PostgreSQL（2026-11-07 从 MySQL 换过来），迁移用 dbmate（`apps/blog/db/migrations/`）。
- 角色：管理员（只有一个）、版主和普通用户；2026-10-30 起普通用户开通 `write` 后也能写自己的文章。普通用户注册要验证邮箱，可以找回密码（SMTP，libcurl）。两步验证（TOTP）都是可选的，管理员也一样。
- 评论必须登录，默认直接显示，管理员可以隐藏、删除、封禁（账号为主，IP 为辅）。两层显示 + "回复 @某人"。
  每个用户在同一篇文章下最多 1024 条评论。邮箱不公开，不接 Gravatar。
- 文章网址用手填的英文 slug，改 slug 后旧地址 301 跳转。
- 界面中英文双语，文章可以有可选的译文；网址 `/zh/...`、`/en/...`，两种语言都预渲染。
- 前端：React + Vite + TypeScript、React Router framework 模式（现在是 8.x）（公开页预渲染、后台 SPA）、TanStack Query、
  Tailwind v4 + shadcn/ui + typography、Zod（同时校验接口响应）+ React Hook Form、Zustand（需要时）、
  ESLint + Prettier、Vitest + RTL + MSW、Playwright（连真实后端）、pnpm。
- 发布、修改、删除文章后，服务器自动重新构建静态页（10 秒防抖，原子替换目录，失败保留旧版本）。评论由浏览器加载，不预渲染。
- 部署：服务器直接对外（2026-10-24 起不用 nginx：TLS、静态文件、gzip、超时和连接数限制由服务器自己做）+ systemd，域名占位 `blog.example.com`。
- 按里程碑提交（现在在 `main`），commit 信息用英文、不加署名；不推送、不开 PR，等作者确认。
- 游戏后端的功能（AOI、服务器拆分等）以后再做；二进制协议（docs/32）和 KCP（docs/33，目前只接在 arena 上）已经有了。

## 默认细节（已确认）

| 项 | 做法 |
|---|---|
| 管理员账号 | 命令行 `blog --create-admin` 创建，加 `--totp` 同时开两步验证并输出 otpauth 链接（不加的话之后在账号页开）；普通用户在网页注册 |
| 邮件链接 | 一次性；注册验证 24 小时、重置密码 1 小时有效；数据库只存 token 的 SHA-256 |
| GitHub、Google 登录 | 第一次登录用对方验证过的邮箱建账号（没有密码）；邮箱已被注册时不自动合并，要先用密码登录再在账号设置里绑定；开了两步验证的账号（包括管理员）回来后还要输验证码；微信、QQ 需要 ICP 备案，服务器在国外，暂不做 |
| 防刷邮件 | 注册、订阅、找回密码要填服务器自己生成的图形验证码，每张只能用一次；同一个邮箱每分钟最多一封（验证、重置、订阅确认） |
| 用户名 | 3–20 位字母、数字、下划线，不区分大小写唯一；另有显示昵称（可以用中文） |
| 头像 | 账号页上传（浏览器里裁成居中正方形、256 像素、重新编码成 WebP，顺带去掉 EXIF）或一键用已绑定的 GitHub/Google 头像（服务器下载到本地，读者不直接连 GitHub/Google）；用 GitHub/Google 新建的账号自动带上对方头像；没有头像显示昵称首字加按 id 分配的颜色；显示在评论区、右上角菜单、账号页、后台用户列表 |
| 自己的评论 | 可以删除；发出后 5 分钟内可以编辑，显示"已编辑" |
| 封禁 | 账号临时或永久封禁，带原因；IP 封禁用于批量注册 |
| 多语言 | react-i18next；`/` 由服务器按 `Accept-Language` 跳转；两种语言共用 slug 和评论 |
| 后端提示语 | 只返回错误码，前端翻译；邮件按用户的语言发送 |
| 会话 | 32 字节随机 token，Cookie `HttpOnly; Secure; SameSite=Lax`，库里只存 SHA-256；30 天，访问时续期；改密码作废全部会话 |
| CSRF | 同步令牌，和会话绑定，写请求带 `X-CSRF-Token`，另查 `Origin` |
| 草稿 | 只在后台预览，不进预渲染和 RSS |
| 图片 | 本地 `uploads/`，最大 10 MB，jpg/png/webp/gif，按文件内容判断类型，随机文件名 |
| 时间 | 库里存 UTC，前端按用户时区显示 |
| 分页 | 游标（`published_at, id`） |

# 黑猫星空（`starry-cat` 分支）

界面结构参考 [innei.in](https://innei.in/en)（Shiro 主题），**只参考设计，不搬代码**（Shiro 是 AGPLv3 + 附加条款）。

## 约定（2026-10-21 和作者确认）

- 风格：作者给的四张油画（山坡上大树下的石头小屋），整页固定做背景：浅色是白天（紫色调，树后的阳光），深色是夜晚（星空，窗里亮着灯）；宽窗口用横版，窄窗口用竖版（`web/public/scenery/`）。配色取自画：白天靛紫 + 金色，夜晚蓝绿 + 琥珀色灯光。保留明暗切换。（演变：黑猫 + 黄昏 → 去掉猫的星空与海 → 2026-10-22 换成这组画。）
- 画上的动效：夜里画中本来的星星闪烁、偶尔一颗流星、窗里的灯光轻微摇曳；白天树后的阳光和草地上的光慢慢明暗。用一个和背景同样裁切的 SVG（`slice` = `cover`）按画的像素坐标画，所以任何尺寸都对得上；"减少动态"时不动。画上盖一层半透明的纱保证可读，首页顶部纱更淡、往下读时变浓（CSS 滚动驱动动画）。
- logo 和 favicon 是小屋和树的剪影，窗口是灯光色（夜里会闪）；页脚上方是山坡剪影；加载状态是三颗依次闪的星。
- 字体：正文系统字体；标题、引用用霞鹜文楷（按需分片加载）。
- 新内容类型：日记 Notes（编号网址、心情、天气）、一句话 Thinking、时间线 Timeline、留言板、友链、项目。日记和一句话和文章一样有可选译文。
- 评论和点赞可以挂在文章、日记、一句话和留言板上；点赞（表情回应）只有登录用户，每人每种一次，可以取消。
- 友链：登录用户在友链页申请，作者在后台审核，结果邮件通知申请人。项目：后台手动维护。
- 首页：头像、问候、简介、引言、统计（文章数、字数、天数）、社交链接、最近内容；个人信息在后台"站点设置"里改。
- 实时：WebSocket 走 rooftree-server 的统一主循环；每页显示"正在看这页"的人数，页脚显示全站在线；有新内容时提示。
- 订阅：任何邮箱，双重确认，每封带一键退订；登录用户在账号页开关。发布文章自动群发，日记发布时可勾选是否群发。
- 图片占位：后台上传时在浏览器里算 thumbhash 和宽高，跟图片一起存，前端先显示模糊图，避免布局跳动。
- 依然：公开页预渲染、评论和实时数据在浏览器加载；按里程碑提交到 `starry-cat`，不推送、不开 PR。
